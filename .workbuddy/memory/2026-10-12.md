## 在真实 MySQL 8.0.46 上实测通过（证据已写进文档 §10）

- 技术设计 §3.1 的 DDL 可直接执行；4 个索引按预期创建（PRIMARY / uq_gotask_queue_idempotency /
  ix_gotask_claim / ix_gotask_lease / ix_gotask_cleanup）。
- 唯一索引**允许多个 NULL**（同队列 2 条 NULL 幂等键都插入成功）→ 幂等键可选，语义正确。
- 重复 `(queue, K1)` → `ERROR 1062 Duplicate entry`；不同队列同 key 可共存 → 作用域是队列级。
- `EXPLAIN` 领取查询：`key=ix_gotask_claim`、`type=range`、**`Extra=Using index`（覆盖索引）**；
  回收查询：`key=ix_gotask_lease`、`Using index`。
- `GET_LOCK` 首次返回 1、`RELEASE_LOCK` 返回 1、`IS_USED_LOCK` 返回持有连接 id。
- **`SKIP LOCKED` 实测**：会话 A 锁 id=1 期间，会话 B 立即拿到 id=2，不阻塞 → 多 Worker 领取设计成立。

## 本机 MySQL 设置（影响 DDL 写法）

- `innodb_default_row_format=dynamic` → InnoDB 索引前缀上限 **3072 字节**，
  所以 `VARCHAR(64)+VARCHAR(191)` 的唯一索引完全够用（不必被迫缩到 191 以内，那是老版本 767 字节的限制）。
- `sql_mode` 含 `STRICT_TRANS_TABLES`；`lower_case_table_names=0`；时区 `+00:00`；隔离级别 `READ-COMMITTED`。
- 探针库 `gotask_probe` 已用完即删；业务库为 `gotask`。

## 关键设计结论（写代码时要落实）

- 版本记录表 `gotask_schema_migrations(version PK, name, applied_at, dirty TINYINT)`。
- **先标记后消除**：开始版本 N → `INSERT (N, dirty=1)`；成功 → `dirty=0`；失败保持 1。
  启动时发现任何 `dirty=1` → **拒绝迁移并报错**（对齐需求 §6.2 不静默继续）。
- **`GET_LOCK` 是会话级的** → 必须用 `db.Conn(ctx)` 固定一条连接跑完
  取锁/迁移/释放，否则连接池会换连接导致锁失效。
- 迁移文件**按解析出的数字排序**（不是文件名字典序）。
- 已应用的迁移文件**不可再改**，只能新增更大版本号。
