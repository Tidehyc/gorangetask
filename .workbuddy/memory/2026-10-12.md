## 关键设计结论（写代码时要落实）

- 版本记录表 `gotask_schema_migrations(version PK, name, applied_at, dirty TINYINT)`。
- **先标记后消除**：开始版本 N → `INSERT (N, dirty=1)`；成功 → `dirty=0`；失败保持 1。
  启动时发现任何 `dirty=1` → **拒绝迁移并报错**（对齐需求 §6.2 不静默继续）。
- **`GET_LOCK` 是会话级的** → 必须用 `db.Conn(ctx)` 固定一条连接跑完
  取锁/迁移/释放，否则连接池会换连接导致锁失效。
- 迁移文件**按解析出的数字排序**（不是文件名字典序）。
- 已应用的迁移文件**不可再改**，只能新增更大版本号。

开工前和用户确认的四个决策（都用推荐项）：
1. 实现放**新建 `store/mysql`**（package `mysql`），`migrations/mysql`（package `mysqlmigrations`）
   保持独立包不动 —— `embed` 不能跨目录向上取文件，并入 store 就得把 .sql 搬进 store 目录，
   而迁移是「建表」的完整闭环、已有独立测试，store 只读表不建表，职责不重叠。
2. **新增 `ClientConfig`**（DefaultQueue / DefaultMaxAttempts / MaxPayloadSize），与 Worker 的
   `Config` 分开。技术设计 §7 原本就写了「Worker 与 Client 配置」，这次才落地。
3. **空 payload 直接拒绝**（`ErrInvalidPayload`），不替调用方补 `null`。
4. **Enqueue + EnqueueTx 一起做**（共用同一套校验与同一条 INSERT）。

实现要点（都写进了代码注释）：
- `Enqueue`/`EnqueueTx` 只差「在谁的连接上执行」：内部接口 `execer` 同时被 `*sql.DB`
  和 `gorangetask.Tx` 满足。
- **`run_at` 以固定格式 UTC 字符串绑定**（`2006-01-02 15:04:05.000000`），而不是传 `time.Time`。
  理由：go-sql-driver 按 DSN 的 `loc` 格式化 `time.Time`，调用方若把 loc 设成非 UTC，
  写入值就会和 SQL 侧的 `UTC_TIMESTAMP(6)` 差一个时区；格式化成 UTC 字符串彻底绕开。
  零值走 SQL 的 `COALESCE(?, UTC_TIMESTAMP(6))`。
- **空幂等键必须绑 NULL 而不是空串**：唯一索引 `(queue_name, idempotency_key)` 不约束 NULL，
  但会把 `''` 当真实取值 —— 写成空串会让同队列第二条「无幂等键」任务被误判为
  `ErrDuplicateTask`。这条单独有集成测试守着。
- 列宽按**字符数**（`utf8.RuneCountInString`）而非字节：`VARCHAR(n)` 在 utf8mb4 下按字符计。
  在 Go 侧先拦，避免调用方拿到 MySQL 严格模式的 1406。
- 只把 1062 翻译成 `ErrDuplicateTask`，其余数据库错误带 `insert task:` 上下文原样冒泡。
- 实测：8 协程并发同键入队连跑 10 轮全部「恰好 1 成功 + 7 个 ErrDuplicateTask」，
  **没有出现 1213 死锁** —— 单条 INSERT + 唯一索引这条路足够稳，不必加重试。

实测证据（一次性 demo，产物在 `/home/tide/.cache/gotask-enqueue-demo/`，仓库外）：
- 重复键真实报错：`gorangetask: duplicate task: queue "orders" already has a task with idempotency key "order-1002"`
- 空 payload 真实报错：`gorangetask: invalid payload: payload is required`
- `EnqueueTx` 提交前事务外可见 0 行、提交后 1 行。
- 一个副作用值得知道：重复键失败的那次 INSERT **仍会消耗一个 AUTO_INCREMENT**，
  所以实际 id 会出现空洞（demo 里 id=4 缺失）。这是 InnoDB 的正常行为，不是 bug。

测试：单测 35 个子用例 + 12 个真 MySQL 集成测试；`store/mysql` 覆盖率 98.4%
（唯一未覆盖是 `LastInsertId()` 报错分支，实际无法构造）；`go test -race ./...` 全绿。

## 坑：集成测试并发跑包时互相删表

`go test ./...` 默认并发跑不同包。`migrations/mysql` 和 `store/mysql` 的集成测试 setup 都是

`CREATE DATABASE IF NOT EXISTS`。每个新加的集成测试包都应取一个独立后缀。
（`go test ./...` 不设 DSN 时全部 skip，CI 不受影响。）

## 两点教训（值得记住）

1. `go test` 的**退出码不反映"测试被跳过"**：集成测试全 skip 时退出码仍是 0。
   所以"CI 绿了"不等于"集成测试跑了"——必须显式检查 SKIP，这正是守门步骤存在的理由。
