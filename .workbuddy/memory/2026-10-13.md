# 2026-10-13 GoRangeTask

## 开工前确认（用户三选一，均取推荐项）—— 决定「永久失败」怎么表达

进入 §3 Worker 执行闭环第一项「Handler 注册与 payload 解码」前，和用户确认三件事：

1. **永久失败用 `Permanent(err)` 包装函数**，而不是新增要 `%w` 包装的公开哨兵错误。
   理由：调用方只需记住 `Permanent`/`IsPermanent` 两个函数，不会因为漏包一层就把
   「重试没意义」的失败当成可重试错误，白白重试到次数耗尽。
2. **库提供 `TypedHandler[T]` 泛型适配器，让解码失败由库自己兜住**（不是靠调用方自觉）。
   payload 是入队时就固定下来的值，解不出来 ⇒ 重试也不会好。
3. **未知 task type 直接进 dead**（对齐技术设计 §6）：task_type 同样是入队时定死的。

## 实现（提交 e2c4147 + 文档 6a7a5ae）

- `errors.go`：新增私有类型 `permanentError{err}`（`Error()` + `Unwrap()`），
  `Permanent(err) error`（**nil 安全** → 返回 nil，所以 Handler 里写
  `return gorangetask.Permanent(err)` 不会把成功当失败；重复标记也安全）、
  `IsPermanent(err) bool`（用 `errors.As`，可穿透多层 `%w`）。
  用私有类型而非公开哨兵，是为了让「漏包一层」这个错误不可能发生。
- `handler.go`：
  - `Registry.Resolve(taskType) (Handler, error)`：与 `Lookup` 的唯一区别是错误分类——
    未注册类型返回**带永久标记**的 `ErrNoHandler`（仍可 `errors.Is(err, ErrNoHandler)`）。
    `Lookup` 保持不打标记（它只回答「能不能查到」，不替调用方决定任务命运）。
  - `TypedHandler[T any](fn func(ctx, payload T) error) Handler`：内部 `json.Unmarshal`，
    失败返回 `Permanent(fmt.Errorf("%w: cannot decode payload: %w", ErrInvalidPayload, err))`；
    `fn == nil` 在**构造期 panic**（启动配置错误应尽早暴露，而不是变成一次任务失败）。
- 测试：新增 `errors_test.go`（Permanent/IsPermanent/错误链/消息），
  `handler_test.go` 补 `TestRegistryResolve`、5 类畸形 payload、
  null 解码为零值仍正常调用、nil 函数 panic、错误穿透等。
- 验证：`gofmt -l` 空、`go vet ./...` 干净、**根包覆盖率 100%**、`go test ./...` 全绿。
- 《进度跟踪》§3 第一行标记完成（含证据与提交号）。
